## Confirmed P2: CPU diagnostic batches can alias reused output storage

Location: [notebooks/wp2_backbone_comparison.ipynb, cell m5d-reports,
d_collect_logits](https://github.com/FZhen2450/COS30082_ML_Project/blob/61e303bbed826ef8ccb2157472f62e33090d87cb/notebooks/wp2_backbone_comparison.ipynb#L3303).

The collector appends `output["crop_logits"].float().cpu()` and the analogous
disease output. On CPU with float32 outputs these conversions can return the
original storage. If a predictor reuses its output buffers, a subsequent forward
pass overwrites previously retained batches. The earlier `validate_one_epoch`
implementation explicitly uses `.to("cpu", copy=True)` and avoids this problem.

Reproduced by executing the exact published function definitions in memory:

- Four synthetic scalar inputs 0, 1, 2, 3; batch size 2; CPU; fp32; no channels-last.
- A synthetic `torch.nn.Module` reuses registered `[2,55]` / `[2,175]` buffers,
  placing the input scalar in the first crop/disease logit column.
- All component/composition labels are zero, so the collector's label-order
  checks pass. There are no images, weights, gradients or optimizer steps.

Actual output:

```text
Expected retained first-column values: [0.0, 1.0, 2.0, 3.0]
Returned first-column values:          [2.0, 3.0, 2.0, 3.0]
```

Recommended owner-side correction: snapshot each output using
`detach().to(device="cpu", dtype=torch.float32, copy=True)`, with a CPU reusable-
buffer regression. This preserves the collector's existing float32 output
contract. No WP2 source was changed here. The reproduction does not establish
an error in historical GPU runs, where the CPU transfer allocates new storage,
or in ordinary models that return fresh tensors.

## Confirmed integration gap: anonymous epoch outputs cannot prove image joins

Both the reusable
[train_multitask.py validate_one_epoch](https://github.com/FZhen2450/COS30082_ML_Project/blob/61e303bbed826ef8ccb2157472f62e33090d87cb/train_multitask.py)
and the notebook's `validation-functions` cell return logits and composition
IDs, without original filenames. `_epoch_batch` drops extra target fields such
as `image_name`. Current WP1 `DPDataset` does not emit filenames either.

A synthetic dataset supplied filenames and identical labels for four samples.
Sequential versus reversed loaders produced different logit row order, identical
returned truth arrays, and no filename field. Thus matching labels/counts alone
cannot prove a paired image join. The accepted development loaders use sequential
validation order; this finding does not imply they were shuffled historically.

WP5 must not attach the approved manifest's names to arbitrary anonymous outputs.
Use an owner-verified producer that exports each original filename alongside its
canonical score/ranked-ID row, or supply independent immutable ordered-identity
evidence. The local `ModelOutputAdapter` requires explicit names and rejects the
anonymous epoch dictionary. This is an integration requirement, not a claim
that accepted aggregate WP2 metrics are wrong.

## Selected checkpoint loading is notebook-specific

The reusable `multitask_backbones.py` factory supports ResNet18, EfficientNet-B0
and ConvNeXt-Tiny. Its `train_multitask.py` loader consequently cannot reconstruct
the selected ConvNeXt-Base checkpoint. The notebook has the B3/Base factory and
the explicit legacy-resolution policy needed for the selected 224 × 224 epoch-1
checkpoint. Do not substitute the generic loader, Tiny, a native preset, or the
later run-plan resolution for that checkpoint.

This distinction is documented legacy/reference scope, not a newly demonstrated
model-factory defect. Real loading remains an external owner-side dependency.
The WP5 adapter consumes already canonical scores and validates the explicit
`multitask_convnext_base`, epoch 1, input resolution 224 declarations.
